Operating mode

1 UPS devices

Monitor one or more UPS devices — via SNMP (UPS with its own network card) or via a NUT server, which is how USB and serial UPS devices are read. For servers with redundant power supplies use one UPS per feed — the mapping is done in step 2. Optional per-UPS thresholds override the global values from step 3.

2 Proxmox hosts (VE / Backup Server)

Pick the type per target: Proxmox VE needs a token with Sys.PowerMgmt, Proxmox Backup Server one with Sys.PowerManagement. The host marked ★ “This host” (the appliance) is shut down last.

Cluster preparation Beta

This appliance

The node this guest runs on is shut down last; the “this host” mark on that host card follows this selection automatically.

This container must not live on Ceph storage. Once the OSDs of the nodes going down drop the pool below min_size, its own disk stops answering and it can no longer shut anything down — halfway through the outage. Use a local storage (local-lvm, local-zfs).

Off by default, and that is the safer setting: if the preparation fails, the HA manager stays armed and stops the guests itself — noisier, but the machines still come down. Switching this on means a failed preparation leaves the whole cluster running until the battery is empty and the power simply goes.

Empty by default (fail-safe): an SNMP loss triggers no shutdown, because it is usually a network/UPS defect and not a power outage. Only set this when a prolonged communication loss should deliberately be treated like an outage — the actual power state is unknown then.

4 Notifications (optional)

Every notable event is POSTed to each enabled webhook. Add one target per chat or monitoring system — a failing target never affects the shutdown.

5 System

Time and timezone are controlled by the Docker host / orchestrator, not by this container.

History

About 1,440 values per UPS and day — a few MB per UPS over 90 days. Not part of the configuration backup. Switching it off stops both the recording and the History tab; what was recorded stays until it ages out or is cleared.

Backup & transfer

Save the configuration as a JSON file or restore it — ideal for reinstalls or migration.

The export file contains credentials in plain text (SNMP community, API token). Store it safely!
